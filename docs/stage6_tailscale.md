# Stage 6 — Tailscale로 로봇을 다른 네트워크에서 붙이기

**목표**: 로봇이 AGX와 같은 LAN에 없어도 뇌에 붙는다. 학교 밖 시연, 로봇 이동, 원격 실험.

**브랜치**: `stage6-tailscale`. 작업 전 상태는 `main` (`d8f2783`, Stage 4 완료).

---

## 지금 무엇이 바뀌는가 — 코드는 거의 안 바뀐다

| | 지금 | Stage 6 이후 |
|---|---|---|
| 로봇이 붙는 주소 | `ws://192.168.0.5:8765` | `ws://<AGX이름>.<tailnet>.ts.net:8765` |
| 로봇 코드 변경 | — | **없음.** `.env`의 `BRAIN_URI` 한 줄 |
| 뇌 코드 변경 | — | **없음.** 이미 `0.0.0.0`에 바인딩한다 |

뇌 서버가 `0.0.0.0:8765`를 듣고 있어서 tailnet 인터페이스는 **자동으로 포함**된다. 즉
Stage 6의 본체는 코드가 아니라 **네트워크 설정과 검증**이다.

그리고 재연결/대화 복구는 **이미 구현돼 있고 로컬에서 검증됐다**
(`client/test_reconnect.py`, 스펙 §11.5). Tailscale이 원래 그것을 위해 만들어둔 기능을
처음으로 실제로 쓰게 만드는 것이다 — §20 규칙 18이 "재연결 루프를 죽은 코드로 지우지 말라"고
적어둔 이유가 이것이다.

## 순서

### 0. 사전 확인 (완료, 2026-09-28)

```
tailscale       미설치
OS              Ubuntu 22.04.5 (jammy) arm64
인터페이스       eno1 192.168.0.5 (유선, UP) / wlP1p1s0 (무선, DOWN·NO-CARRIER)
```

⚠️ **무선이 내려가 있다.** 9월 중순엔 `192.168.0.247`이 잡혀 있었다. 유선만으로도 tailnet은
되지만, 로봇을 들고 이동하는 시연이라면 AGX 쪽 회선이 무엇인지 확인해둘 것.

### 1. 설치 — 🔴 사용자 승인·조작 필요

시스템 패키지 설치이고 **외부 네트워크에 기기를 합류시키는 일**이라 승인 없이 하지 않는다.
그리고 `tailscale up`은 **브라우저 인증**을 요구하므로 사용자가 직접 해야 한다.

```bash
curl -fsSL https://tailscale.com/install.sh | sh     # jammy/arm64 지원
sudo tailscale up                                     # 출력되는 URL로 로그인
tailscale status
tailscale ip -4                                       # 100.x.y.z
```

로봇에서도 같은 절차로 같은 tailnet에 합류시킨다(로봇 소유 작업).

### 2. 🔴 `direct`인지 확인 — Stage 6의 핵심 게이트

```bash
tailscale status          # 로봇 줄 끝에 "direct ..." 여야 한다
tailscale ping <robot>    # "via DERP" 가 아니라 "via <ip>:<port>" 여야 한다
```

**`relay`면 성능 저하 모드로 취급한다.** DERP 릴레이는 WireGuard 트래픽을 중계 서버로
우회시키고, 그 지연이 **음성 루프에 그대로 들어온다**(스펙 §18, Q15). NAT 종류에 따라
갈리므로 양쪽 네트워크를 바꿔가며 확인해야 한다.

### 3. 지연 재측정

```bash
# 로봇에서 BRAIN_URI를 tailnet 이름으로 바꾼 뒤
PYTHONPATH= .venv_tts/bin/python client/exp8_latency.py --real 8   # (AGX 로컬 기준선)
```

비교 기준은 **실물 로봇 중앙값 약 2.0초**(같은 LAN, 2026-09-23). 여기서 얼마나 늘어나는지가
Q15의 답이다. 오디오 대역폭 자체는 문제가 아니다 — 업 256kbps / 다운 384kbps로, 어떤
현실적인 링크에도 부담이 아니다(§13).

### 4. 링크 끊김에서 대화가 살아남는지

로컬에서는 통과했지만 **실제 링크의 실패 양상은 다르다** — half-open 연결, NAT 재바인딩,
절전/복귀. 실제로 해볼 것:

- 로봇 쪽 네트워크를 끊었다 붙인다 (WiFi 토글)
- AGX 쪽에서 `tailscale down` → `up`
- 로봇을 다른 네트워크로 옮긴다 (테더링 등)

각 경우에 **끊기기 전 대화를 기억하고 있는지** 물어본다. 뇌가 `session_id`로 세션을 들고
있고 `ready`에 `resumed`와 이어받은 턴 수를 실어 보낸다.

뇌 로그에서 볼 줄: `session ...: resumed, N turns carried over`
그리고 끊길 때 `robot disconnected (code=..., ...)` — 이유가 남는다.

### 5. 문서 갱신

`docs/robot_integration.md`의 "전제: 같은 LAN"과 `BRAIN_URI` 기본값, README의 아키텍처 그림
각주를 고친다.

## ⚠️ 먼저 정해야 할 것 — 뇌에는 인증이 없다

지금 뇌 서버는 **누가 붙어도 받는다.** 같은 LAN(집·연구실 라우터 뒤)에서는 그냥 느슨한
정도였지만, tailnet에 올리면 성격이 조금 달라진다.

tailnet은 기본적으로 사설이고 기기 단위로 인증되므로 **LAN보다 오히려 안전하다.** 다만 그
tailnet에 있는 **모든 기기**가 다음을 할 수 있다:

| 열려 있는 것 | 할 수 있는 일 |
|---|---|
| `:8765` 뇌 | 세션을 열고 페르소나를 넣어 모델과 대화. 토큰을 태운다 |
| `:8766` 모니터 | **대화 전사를 실시간으로 본다** — 상담 대화가 주제라 민감하다 |

또 `SESSIONS`는 **클라이언트가 보낸 `session_id`로 키를 잡는다**(§11.5). uuid4라 추측은
비현실적이지만, id를 아는 쪽은 그 대화를 이어받을 수 있다. 설계상 의도된 동작이고(로봇
재연결이 그걸로 돈다) tailnet 안에서는 문제가 아니지만, 기록해둘 값어치는 있다.

**권하는 조치: Tailscale ACL로 두 포트를 로봇 기기에만 연다.** 태그를 붙이고
(`tag:robot`, `tag:brain`) ACL에서 `tag:robot → tag:brain:8765`만 허용하는 식이다.
모니터(`:8766`)는 개발용이니 필요할 때만 열거나 아예 tailnet에 안 여는 쪽이 낫다.

이건 뇌 코드가 아니라 tailnet 설정이라 **사용자 판단**이다.

## 하지 않을 것

- **포트 포워딩·공개 인터넷 노출** — 인증이 없는 서버를 열어둘 이유가 없다.
  Tailscale을 쓰는 이유 자체가 이걸 피하는 것이다
- **뇌에 자체 인증 추가** — tailnet의 기기 인증이 이미 그 역할을 한다. 필요해지는 건
  tailnet 밖에 노출할 때이고, 그럴 계획이 없다
- **`tailscale cert` / Serve로 TLS** — `ws://`로 충분하다(WireGuard가 이미 암호화한다).
  단 **브라우저 테스트 클라이언트를 claude.ai 아티팩트에서 쓰고 싶어지면** 그때 필요하다
  (HTTPS 페이지에서 `ws://`가 mixed content로 막히는 문제, `web/README.md`)
