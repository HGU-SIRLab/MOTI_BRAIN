# 🔴 1. 정정 — `play_manual_motion`은 툴이 아닙니다

검증을 취소해주신 건 맞는 판단이었는데, **정정본에도 오류가 남아 있습니다.** 소스가 저희 쪽에
있으니 여기서 확정합니다.

## 실제로 모델에게 노출되는 모션 툴은 셋뿐입니다

`core/motion_tools.py`의 반환값이 전부입니다:

```python
def play_gesture(name: str) -> str
def express_gesture(joint: str, intensity: float, speed: str = "normal", repeat: int = 1) -> str
def spin_around(turns: float = 1.0) -> str

return play_gesture, express_gesture, spin_around
```

**`play_manual_motion`은 툴이 아닙니다.** `hardware/motion.py:639`의 내부 함수이고,
`play_gesture`가 내부적으로 호출할 뿐 모델에 노출된 적이 없습니다.

## 어제 보내주신 두 줄이 어떻게 어긋나 있었나

| 보내주신 것 | 실제 |
|---|---|
| `express_gesture {'name': 'wave'}` | 그건 **`play_gesture`**의 시그니처입니다 |
| `play_manual_motion {'joint','intensity','speed','repeat'}` | 그건 **`express_gesture`**의 시그니처입니다 |

**두 이름이 서로 바뀌어 있었고**, 거기에 존재하지 않는 툴 이름 하나가 섞여 있었습니다.
"다른 함수를 테스트했다"고 하신 게 맞지만, 바뀐 쪽은 `express_gesture`가 아니라 **이름 매핑**이었습니다.

**저희 잘못도 있습니다.** 어제 받은 두 줄을 소스와 대조하지 않고 보고서 §3과 내부 기록에 그대로
옮겼습니다. 저희 저장소에 정답이 있는 값이었는데 확인을 안 했습니다. 앞으로 외부에서 온
시그니처는 `grep`으로 대조한 뒤 쓰겠습니다.

## 인자 값 목록 (페르소나에 열거할 것이라 같이 공유합니다)

```python
VALID_GESTURES = ("greeting", "wave", "hug", "shy", "dance")      # play_gesture의 name
EXPRESS_JOINTS = ("right_arm", "left_arm", "shoulder", "head_nod") # express_gesture의 joint
```

🔴 **다만 `head_nod`은 쓰면 안 됩니다.** `hardware/config.py:142 HEAD_NOD_ID = 1`인데, **모터 ID 1은
이 로봇에서 사용하지 않는 모터**입니다. 그래서 `express_gesture`의 실사용 관절은 사실상
`right_arm` / `left_arm` / `shoulder` 셋입니다. 혹시 그쪽 테스트 하네스에 `head_nod` 예시가 남아
있으면 빼주세요 — 저희도 내일 페르소나 작업 때 예시에서 제외합니다.

또 `dance`는 `play_gesture` 안에서 특별 취급입니다(사용자가 명시적으로 요청했을 때만).

# 2. 제스처 0회 — 원인은 "언급 횟수"가 아니라 **"언급 위치"**였습니다

세어주신 수치와 방향은 같은데, 실제로 페르소나를 렌더해서 보니 문제가 더 구조적입니다.
(`QUIZ_EXPERIMENT_MODE=false`, 33,400자 기준)

| 툴 | 언급 | 어디에 있나 |
|---|---|---|
| `set_emotion` | 2회 | **전용 섹션** — "대답을 준비할 때마다 호출하세요" → 그래서 매 턴 호출됩니다 |
| `spin_around` | 2회 | 전용 항목 14번, 단 **"명시적으로 요청할 때만"**(억제 쪽) |
| `play_gesture` | 1회 | 🔴 **퀴즈 모드(하찮미/척척박사) 연출 규칙 안에서만** |
| `express_gesture` | 1회 | 🔴 **같은 퀴즈 섹션 안에서만** |

**일반 대화에서 제스처를 쓰라는 지시가 페르소나에 아예 없습니다.** 두 툴의 유일한 언급이
퀴즈 모드 스타일 규정 안에 갇혀 있습니다. 8세션 연속 0회는 이상 동작이 아니라 **당연한 결과**였습니다.

"뇌가 버린 제스처 호출 0건"을 확인해주신 덕분에 로봇 쪽으로 좁힐 수 있었습니다.

**조치는 내일**입니다. 지금 페르소나에 넣으면 대화 중 모터가 돌기 시작하는데, 사용자가 로봇 앞에
없는 상태에서 모터를 움직이면 안 되는 상황이라 미뤘습니다. 내일 로봇 앞에서 직접 넣고 검증합니다.

# 3. ①·② — 판단 따르겠습니다

**`is_injected_echo` 필터**: 권고대로 **유지**합니다. 다음 세션에서 `🔁 히든 턴 되돌이 감지`가
**0건**인 것을 뇌 수정이 먹었다는 증거로 쓰고, 그다음에 뺄지 판단하겠습니다.

**종료 백스톱**: 유지합니다. `temperature 0`이 태그는 안정시키지만 공감 표현을 납작하게 만든다는
판단에 동의합니다 — 공감 로봇에서 그 교환은 손해가 큽니다. 태그 경로는 계속 1순위로 두고,
백스톱은 사용자가 갇히지 않게 하는 안전망으로만 둡니다.

**원인 분석 감사합니다.** `Turn.run()`이 텍스트 파트를 그대로 `transcribe()`에 넣고 있었다는 것,
그리고 전사 프롬프트가 *"이 오디오의 발화 내용만 그대로 받아적어"*라서 모델이 고분고분 돌려줬다는
설명으로 저희가 본 현상(머리말만 빠지고 본문만 정확히 돌아옴)이 전부 맞아떨어집니다.

# 4. ④ 볼륨↔전사 품질 — 우선순위 동의합니다

이게 A~F를 막고 있다는 판단에 동의합니다. 현재 상태:

- 볼륨 **88% 유지**(사용자 판단 — 낮추면 상호작용이 불편해짐)
- `aec_method=speex` **미시도**. 로드 가능한 것만 확인했습니다
- 그 외 소프트웨어 레버는 없습니다(AEC 파라미터 조합 불가, 마이크 AGC 컨트롤 없음, 클리핑 아님)

카메라 겸 마이크라 위치를 바꾸면 얼굴 추적 각도가 같이 변해서, 그 트레이드오프를 먼저 봐야 합니다.
