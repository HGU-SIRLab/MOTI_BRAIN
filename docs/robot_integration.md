# 로봇 쪽 작업 지시서

`MOTI-HRI` (`jetson-moti` 브랜치, Jetson Orin Nano Super)를 로컬 뇌에 붙이는 절차.
뇌는 AGX Orin에서 이미 돌고 있고, **로봇 코드 변경은 한 줄 + 설정 두 개**다.

전제: 뇌(AGX)와 로봇이 같은 LAN. 원격은 Stage 6(Tailscale)이고 아직 미착수.

**뇌 상태 (2026-09-21 11:50 확인)**: vLLM·뇌 서버 모두 가동 중, `192.168.0.5:8765`.
미지 사용자 페르소나는 **예열해 두었다** — 첫 인사가 0.2초에 나온다
(자세한 건 §4의 「첫 인사」 항목).

## 이게 무슨 작업인가 — 로봇 쪽에서 처음 읽는 사람/에이전트용

### 한 줄

**로봇이 Gemini Live API에 하던 것과 똑같은 방식으로 말을 걸면, 젯슨 AGX Orin 위의 상시
서버가 그 오디오를 듣고 한국어로 공감하는 음성과 로봇 동작 지시를 돌려준다.** 클라우드가
사라지고 그 자리에 우리가 만든 뇌가 들어간다.

동기는 비용과 rate limit이다. 지금 구성은 세션마다 18,344토큰짜리 페르소나를 Gemini에
올리고 있고, 그게 요금의 큰 몫이다.

### 누가 무엇을 담당하는가

```
┌─ 로봇: Orin Nano 8GB ─────────┐        ┌─ 뇌: AGX Orin 64GB ───────────┐
│ 마이크 · AEC · 스피커          │◄──────►│ VAD → 턴 감지 → Gemma 4 E4B   │
│ 카메라 · 얼굴인식 · 모터 · 표정 │ 오디오 │ → Piper TTS                    │
│ 툴 실행 (remember_fact 등)     │ + JSON │ 대화 상태 보관·재연결 복구      │
│ launcher.py — connect() 한 줄  │        │                                │
└────────────────────────────────┘        └────────────────────────────────┘
                    같은 LAN, 웹소켓 :8765
```

**로봇이 계속 담당하는 것**: 마이크 캡처, AEC, 스피커 재생과 중단, 카메라/얼굴인식,
모터, 그리고 **모든 툴의 실제 실행**. 뇌는 "무엇을 하라"고만 말하고 직접 하지 않는다.

**뇌로 옮겨간 것**: 음성 구간 검출(Silero VAD), 턴 종료 판단(smart-turn-v3), 언어 모델,
음성 합성, 대화 기록.

### 알아둘 것 세 가지

**① 턴 경계는 뇌가 정한다.** Gemini Live가 서버 쪽 VAD를 하고 있었기 때문에 `launcher.py`의
`send_loop()`은 마이크 청크를 **조건 없이 계속** 보낸다. 우리도 그 계약을 그대로 유지한다.
→ **로봇에 VAD를 추가하지 말 것.** 오디오 경로는 손대지 않는다.

**② STT가 없다.** Whisper 같은 음성인식 단계가 파이프라인에 없다. Gemma 4 E4B가 오디오를
**직접** 받고, 말의 내용뿐 아니라 **말투(운율)까지 듣는다**. 같은 문장을 톤만 바꿔 녹음한
실험에서, 억눌린 슬픔으로 "괜찮아"라고 말하자 모델이 *"괜찮다고 말했지만, 사실은 많이
신경 쓰이고 힘든 마음이 느껴져요"* 라고 답했다. 사용자 발화의 전사도 같은 모델이 만들어
`input_transcription`으로 보낸다.

**③ 로봇 코드 변경이 한 줄인 이유.** `core/local_live.py`(이번에 복사하는 파일)가
`google.genai`의 라이브 세션과 **똑같은 겉면**을 흉내낸다 — `send_realtime_input`,
`send_client_content`, `send_tool_response`, 그리고 턴 경계에서 끝나는 `receive()`
비동기 제너레이터까지. 그래서 `recv_loop`, 툴 실행, 전사 처리, 재연결 루프가 **수정 없이**
그대로 돈다. `launcher.py`의 수신 루프를 구조 그대로 재현한 테스트가 통과한다.

### ⛔ 하지 말 것

이 목록은 취향이 아니라, 하나하나 이유가 있어서 적는다.

| 하지 말 것 | 이유 |
|---|---|
| **`core/local_live.py` 수정** | 로봇에서 돌지만 **뇌 저장소 소유**다. 테스트 8종이 AGX에서 돌고, 여기서 고치면 다음 `scp`에 사라진다 (위 ⛔ 규칙) |
| `launcher.py` 구조 변경·리팩터링 | 바꾸는 순간 검증된 코드가 아니게 된다. 변경은 540행 한 줄 + import 두 줄이 전부다 |
| 로봇에 VAD 추가 | 턴 경계는 뇌가 정한다(위 ①). 양쪽에서 판단하면 서로 싸운다 |
| `OUTPUT_RATE = 24000` 변경 | 뇌가 Piper의 22,050Hz를 24kHz로 변환해서 보낸다. AEC 참조 경로와 `snore.wav`도 이 값에 묶여 있다 |
| 재연결 루프(`connection_manager`) 삭제 | 죽은 코드처럼 보이지만 Stage 6(Tailscale 원격)에서 필수다. 뇌가 대화 상태를 들고 있다가 복구한다 |
| `.env`의 `GOOGLE_API_KEY`를 비우기 | `launcher.py:211`이 비어 있으면 대화를 시작하지 않고 반환한다. 아무 값이나 있으면 되고, 어디에도 전송되지 않는다 |

### 뇌가 보내는 메시지 (로그를 읽을 때 필요)

`{"t":"ready"}` `{"t":"audio"}`+바이너리 PCM `{"t":"transcript"}` `{"t":"tool_call"}`
`{"t":"interrupted"}` `{"t":"error"}` `{"t":"turn_complete"}` — 7종이고 shim이 전부
Gemini 쪽 필드로 번역한다. `tool_call`의 `args`는 **문자열이 아니라 dict**다
(`launcher.py`가 `fn(**(fc.args or {}))`로 펼치기 때문).

### 지금까지 검증된 것과 안 된 것

뇌 쪽은 단위 검사 8종이 통과했고, 가짜 로봇 클라이언트로 왕복도 확인했다 — 실시간 스트리밍,
턴 감지, 끼어들기(0.07초), 툴 왕복, 재연결 후 대화 복구, 지연 평균 2.65초.

**그러나 전부 가짜 로봇 기준이다.** 실제 마이크, AEC, 스피커 재생, 모터·카메라 동시 구동은
**한 번도 검증된 적이 없다.** 이번 작업이 그 첫 번째다. 그래서 아래 §4의 확인 순서가
위험도 순으로 정렬돼 있다.

## ⛔ 가장 중요한 규칙 — 어느 쪽 문제인지부터 진단한다

이 시스템은 **Claude Code 두 개**가 나눠 작업한다. 하나는 AGX(뇌 저장소 `MOTI_BRAIN`),
하나는 로봇(`MOTI-HRI`). **어느 쪽도 상대편 코드를 고치지 않는다.**

2026-09-21에 로봇 쪽에서 `core/local_live.py`를 직접 고치기 시작했고, 그래서 이 규칙이
생겼다. 이해할 만한 판단이었지만 틀렸고, 이유가 적어둘 만하다 — **그 파일은 로봇에서
*돌지만* 뇌 저장소가 *소유*한다.** 그걸 검증하는 테스트 8종도 AGX에서 돈다. 로봇에서 고치면
(1) 테스트를 안 거치고 (2) 저장소와 갈라지고 (3) 이 문서가 시키는 다음 `scp` 한 번에
사라진다.

### 소유권 — 버그마다 협상하지 않는다

| 파일 / 영역 | 소유 | 반대편이 하는 일 |
|---|---|---|
| `launcher.py`, `core/`, `media/`, `.env`, AEC, 모터, 카메라 | **로봇** | 증상을 보고한다 |
| `brain/`, **`core/local_live.py`**, `scripts/`, 스펙 문서 | **뇌 (AGX)** | 증상을 보고한다 |

`local_live.py`가 함정이다. 로봇에 배포되지만 뇌 저장소 것이다. **수정은 AGX에서 하고,
거기서 테스트하고, 푸시하고, 로봇이 다시 복사해 온다. 반대 방향은 없다.**

### 뇌 로그가 심판이다

대부분은 판단이 아니라 기계적으로 갈린다. **뇌가 "보냈다"고 로그에 남겼는가?**
남겼으면 그 아래(로봇) 문제, 안 남겼으면 그 위(뇌) 문제다.

AGX에서: `tail -f /home/herobot/moti_brain/logs/brain.log`

| 증상 | 어느 쪽 | 왜 추측이 아닌가 |
|---|---|---|
| `client silent Ns — closing turn anyway` | **로봇** | 뇌가 오디오를 *못 받고* 있다. 뇌가 만들 수 있는 상황이 아니다 |
| 사용자가 조용한데 `barge-in: turn cancelled` 반복 | **로봇** | 에코가 마이크로 돌아오는 것 — AEC |
| `turn failed` + 트레이스백 | **뇌** | 뇌 파이프라인의 예외 |
| 툴 마크업을 소리내어 읽음 | **뇌** | 뇌의 마크업 제거 로직 |
| 말하는 중에 끊기거나, 끝냈는데 오래 기다림 | **뇌** | 뇌의 VAD 임계값 |
| 소리가 9%쯤 빠르고 높음 | **뇌**(리샘플링) 먼저, `OUTPUT_RATE`를 건드렸다면 로봇 |
| 툴이 실행되지 않음 | 뇌 로그에 `tool_call`이 있나? **있으면 로봇, 없으면 뇌** |
| 대화록에 사용자 발화가 없음 | 뇌 로그에 `transcript role=user`가 있나? **있으면 로봇, 없으면 뇌** |
| 로봇이 아무 에러 없이 멈춤 | 뇌가 `turn_complete`나 `error`를 보냈나? **보냈으면 로봇, 아니면 뇌** |

### 애매하면 — 아무것도 고치지 말고 물어본다

위 표로 안 갈리면 **양쪽 다 한 줄도 건드리지 않는다.** 대신 사용자에게 이렇게 보고한다:

1. 정확한 증상 — 트레이스백은 **그대로**, 또는 뇌 로그 줄을 타임스탬프째로
2. 이미 배제한 것과 **어떻게** 배제했는지
3. 가설 한두 개와, 각각이 어느 쪽에 있을 것인지

사용자가 맞는 쪽으로 전달한다. **틀린 쪽에 추측으로 낸 수정은 기다리는 것보다 나쁘다** —
2026-09-21 현재 이 시스템은 실물 하드웨어로 검증된 것이 하나도 없어서, 변수를 하나 더
얹으면 원래 변수를 찾을 수 없게 된다.

## 0. ✅ AEC — 해결됨 (2026-09-21 실물 확인)

**이 로봇의 AEC는 PulseAudio `module-echo-cancel`(webrtc)이 담당한다.** 기본 sink/source가
`echocancel_*`이고 재부팅해도 살아남는 것을 확인했다. 실물 세션 전체에서 **에코성 barge-in
오탐 0건**이었다.

`aec_audio_processing` 휠은 여전히 없고, 그래서 **`.env`의 `ENABLE_AEC=false`가 맞다** —
앱 레벨 AEC를 일부러 끄고 한 단계 아래에서 처리하는 구성이다. (이 문서의 이전 판본은
"`ENABLE_AEC=false`면 AEC가 없다"고 경고했는데, 이 구성에는 해당하지 않는다.)

확인만 하고 싶으면:

```bash
pactl info | grep -i "Default S"      # echocancel_* 이어야 한다
```

남겨둘 주의사항 하나: `media/audio_manager.py:25-32`의 조용한 자동 비활성화 경로는 아직
있다. 지금은 어차피 꺼두는 게 맞아서 무해하지만, 나중에 누군가 `ENABLE_AEC=true`로 되돌리면
휠이 없다는 사실이 경고 한 줄로만 지나가고 묻힌다.

## 2. `launcher.py` — 한 줄

**540행:**

```python
# 변경 전
async with client.aio.live.connect(model=LIVE_MODEL, config=config) as session:

# 변경 후
async with local_live.connect(BRAIN_URI, config=config) as session:
```

그리고 import 한 줄과 주소 한 줄을 추가한다 (파일 상단, 다른 `from core...` 옆):

```python
from core import local_live
BRAIN_URI = os.getenv("BRAIN_URI", "ws://192.168.0.5:8765")
```

**그 외에는 아무것도 바꾸지 않는다.** `recv_loop`, 툴 실행, 전사 처리, 재연결 루프,

동작한다 — shim이 Gemini Live 세션과 같은 면을 제공한다. 구조를 고치기 시작하면
그때부터는 검증된 코드가 아니다.

## 4. 붙이고 나서 볼 것 — 순서대로

### ① AEC (최대 위험)

로봇이 **자기 목소리에 스스로 끼어드는지**. 뇌의 barge-in은 70ms로 빠르고, 그만큼 잘
자해한다.

**증상**: 모티가 말하는 중에 AGX 서버 로그에 이 줄이 반복된다.

```
INFO barge-in: turn cancelled
```

모티가 말하는 동안 사용자가 조용한데도 이게 찍히면 에코가 마이크로 되돌아오는 것이다.

**응급 조치**: 확인만 하려면 이어폰을 꽂으면 에코 경로가 사라진다(로봇 저장소도 그렇게
격리해 원인을 규명한 적이 있다). 근본 해결은 AEC이고, 그게 §9.2의 `[MANDATORY]`다.

### ② 소리가 정상 속도·음높이로 나는가

뇌가 22,050Hz Piper 출력을 24,000Hz로 변환해 보낸다(로봇의 `OUTPUT_RATE`에 맞춤).
9% 빠르고 높게 들리면 변환이 안 된 것이다.

### ③ 턴이 제때 끊기는가

- **말하는 중에 끊긴다** → `stop_secs`/빠른 경로가 이 마이크·환경에서 너무 공격적이다.
  AGX의 `brain/vad.py`에서 `fast_confidence=0.99`로 바꾸면 빠른 경로가 꺼진다(한 줄).
- **말을 끝냈는데 한참 기다린다** → 거부권이 과하게 붙잡고 있다. `max_wait`를 줄인다.

측정된 기준값: 자연 발화에서 말 멈춤 → 첫 오디오 **평균 2.65초**(p95 5.1초, 최소 1.42초).
이건 로봇이 실제로 보내는 18,344토큰 페르소나 + 툴 9개로 잰 값이다(§13.9). 문서 앞선
판본에 있던 "약 2.0초"는 50토큰짜리 시험용 프롬프트로 잰 것이라 로봇에 적용되지 않는다.

### ⚠️ 첫 인사 — 지금은 데워져 있지만, vLLM을 재기동하면 다시 느려진다

한 번도 프리필되지 않은 페르소나로 **처음** 붙는 세션은 18K 프리필을 통째로 문다 —
첫 소리까지 **실측 17.9초**. `launcher.py`는 연결하자마자 인사 턴을 밀어넣으므로 사람이
앞에 선 채로 그만큼 기다리게 된다.

**2026-09-21에 미지 사용자(`name=None`) 페르소나를 손으로 예열해 두었다.** 얼굴 인식이
실패하거나 미등록인 경우가 이 경로이고, 지금은 0.2초에 인사가 나온다.

주의할 점 두 가지:
- **얼굴 인식이 이름을 찾아내면 다른 페르소나가 되어 예열이 빗나간다.** 사용자 이름은
  프롬프트의 1.17% 지점, `facts_summary`는 3.54% 지점에 들어가므로 캐시가 거의 공유되지
  않는다. 그 사람의 첫 세션은 17.9초를 낸다(한 번만).
- **사람이 그 침묵에 반응하면 더 나빠진다.** 3초쯤에 말을 걸면 barge-in이 0.11초에 인사
  턴을 취소하는데, 프리필이 끝나기 전이라 캐시에 아무것도 남지 않고 그 사람의 발화 턴이
  18K를 처음부터 다시 낸다 → 첫 소리까지 19.7초. 반복해서 말을 걸면 계속 길어질 수 있다.

근본 해결(뇌 기동 시 자동 예열)은 스펙 §13.1에 설계만 있고 **구현돼 있지 않다.**
지금의 우회는 vLLM을 끄지 않는 것이다 — 캐시는 그 프로세스가 사는 동안 유지된다.

### ④ 대화 기록이 제대로 저장되는가

세션 종료 후 결과지(마음처방전)와 대화록에 **사용자 발화가 들어있는지** 확인한다.
E4B가 전사를 만들어 `input_transcription`으로 보내는데, 이 경로는 실물에서 확인된 적이
없다. 비어 있으면 연구 데이터가 유실된다.

### ⑤ 툴이 실제로 실행되는가

표정이 바뀌고(`set_emotion`), 제스처가 나오고(`play_gesture`), 이름을 기억하는지
(`remember_fact`). AGX 로그에 `tool_call`이 찍히고 로봇이 결과를 돌려주면 정상이다.

### ⑥ 동시 구동 부하

모터·카메라·표정 UI가 같이 도는 상태에서 오디오가 끊기거나 지연이 늘어나는지.
Orin Nano는 8GB이고 뇌와 달리 여유가 없다.

## 4-B. AGX 쪽 로그 보는 법

뇌가 무엇을 하고 있는지는 여기서 본다:

```bash
# AGX에서
tail -f /tmp/claude-1000/-home-herobot/*/scratchpad/brain.log
```

읽을 줄:

| 로그 | 뜻 |
|---|---|
| `robot connected: (...)` | 핸드셰이크 성공 |
| `barge-in: turn cancelled` | 끼어들기 감지. **사용자가 조용한데 반복되면 에코다** |
| `backchannel (1440ms of silence)` | 맞장구 발화 |
| `speculation adopted (N ready, ...)` | 투기적 생성이 쓰였다 |
| `client silent 6.5s — closing turn anyway` | 스톨 워치독. 오디오가 끊겼다는 뜻 |
| `turn failed` + 트레이스백 | 뇌 쪽 예외. 이게 보이면 그 트레이스백이 필요하다 |

## 5. 되돌리는 법

| 문제 | 되돌림 |
|---|---|
| 뇌 쪽이 아예 안 되는 경우 | `launcher.py` 540행을 원래대로 + `.env`의 `GOOGLE_API_KEY`에 실제 키 → Gemini Live로 즉시 복귀 |
| 말하는 중에 끊긴다 | AGX `brain/vad.py`의 `fast_confidence=0.99` |
| 맞장구("응")가 거슬린다 | 로봇에서 `local_live.connect(..., backchannel=False)` |
| 응답이 느려도 끊기지 않는 쪽을 원한다 | 위 `fast_confidence=0.99`와 같음 |

로봇 쪽 변경이 한 줄이라, **Gemini로 되돌리는 것도 한 줄**이다. 그게 이 설계의 목적이다.
